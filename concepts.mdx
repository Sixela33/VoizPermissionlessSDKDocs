If you remember one thing: **everything hangs off the client.** You never `new VoizMarket(…)`. You say `client.market(addr)`.

```ts
const client = useVoiz().client // or new VoizMarketsClient({ … })

const market = client.market(addr)
const pool = client.pool(outcomeToken, { market: addr, outcomeIndex: 0 })
const user = client.user(owner)
```

## Market vs metadata

`summary` / `listMarkets` are protocol facts: name, outcomes, tokens, resolved or not.

Pictures and copy are **not** on that object. Ask the market:

```ts
const summary = await market.summary()
const metadata = await market.metadata() // { description, resolutionCriteria, image, outcomeImages } | null
```

Want a thumbnail on a catalog card? Call `client.market(row.address).metadata()`. Do not wait for the list to pre-stuff images.

The usual **write** is `client.createMarket({ …, metadata })`. The client deploys, then uploads files and sets `metadataURI`. `market.setMetadata` is there if you ever need a retry.

## Collateral and outcomes

Each market has one collateral token (`client.addresses.collateral`), several named outcome ERC-20s (`wrappedTokens[0..numOutcomes-1]`), and Invalid at index `numOutcomes`.

There is **one** OutcomeAmm per market. A **pool** handle is one named outcome on that AMM: `client.pool(outcomeToken, { market, outcomeIndex })`. Trades go through that handle, not the market address.

Invalid is minted in complete-set splits so CT accounting closes. It is not a tradable named outcome. `market.prices().rows` is **named outcomes only** (`0 .. numOutcomes-1`). Invalid lives at `summary.wrappedTokens[numOutcomes]`. On-chain, `OutcomeAmm.prices()[numOutcomes]` is 0; that extra slot is not on the SDK rows.

Seeding and later LP both call `addFunding` on that single AMM.

## Indexer vs chain

| You want | Use | If the indexer is down |
| -------- | --- | ---------------------- |
| Catalog | `listMarkets`, `summary` | RPC fallback. `listMarkets` returns `{ source: "rpc", usedFallback: true }` |
| Display prices | `market.prices()`, `metrics()` | RPC fallback, `{ source: "rpc" }` |
| Charts / portfolio | `priceHistory`, `user.trades` / `sharePositions` / `lpPositions` | Soft-fail to `[]` |
| A size you can actually trade | `pool.quoteTrade` then `pool.swap` | Live RPC (always) |

Do not treat an empty catalog as “indexer down”. That is the portfolio/history path.

Display prices can lag a bit. Never size a swap from them.

`user.sharePositions()` is the indexer share book only. It does not overlay live ERC-20 balances.

## Quotes vs writes

**Seed:** `quoteSeed({ seedWei, oddsBps })` is pure math (`totalCollateral === seedWei`). `market.seed(…)` is first LP: `addFunding` with named-outcome odds and Invalid weight 0.

**Trade:** `pool.quoteTrade({ side, amountIn })` may cap you (`withinRange: false`). `pool.swap` sends that size. `buy` is collateral → outcome; `sell` is the reverse. You apply slippage to `minAmountOut`.

**LP:** `market.addLiquidity({ credits, owner })` — later `addFunding` joining current proportions. Mechanics and risk: [How liquidity provision works](/market/liquidity).

## How writes go out

Pass `sendCalls` (Privy / AA: many inner calls, one UserOp) or a `walletClient` (each inner call is its own tx).

`requiredSigner` is a hint for an AA sender that has more than one key. A normal wallet ignores it and signs with the connected account.
